Phase 1 — Weeks 1–4
Core Content & Communication Layer

These six modules directly impact daily usage by students, parents, and teachers. They unlock the content and communication layer that is currently CASPAA's biggest gap versus EDVES.

Phase 1

6 Modules · Estimated 3–4 Weeks

Focus: high-visibility, daily-use features that close the learning content gap immediately.

📅
1. Event Calendar
School-wide events visible across all roles
Medium Effort All Roles
Data & Backend
1
Add Events table to DB Fields: id, schoolId, title, description, date, endDate, type (holiday/exam/sports/meeting/other), targetAudience (all/students/parents/teachers), createdBy.
2
Seed sample events Mid-term break, PTA meeting, Sports Day, End-of-term exams, Prize Giving Day — covers current academic term.
3
Compute upcoming events Add COMPUTE.upcomingEvents(userId) — returns next 5 events relevant to the user's role.
UI & Views
4
Admin: Create & manage events New view view_adm_calendar — month grid + list toggle. Add/Edit/Delete events with audience targeting and color-coded types.
5
Teacher & Parent: Read-only calendar Add "Calendar" to teacher and parent menus. Month view with clickable events showing detail panel.
6
Dashboard widgets Add "Upcoming Events" card to Admin, Teacher, Parent, and Student dashboards showing next 3 events.
Technical Notes
  • Month grid: use a pure CSS grid (7 columns) populated by JS — no external calendar library needed.
  • Color-code event types: holiday = red, exam = amber, sports = green, meeting = blue.
  • Re-use existing modal pattern for Create/Edit event form.
Roles: Admin (Create) Teacher (View) Parent (View) Student (View)
📱
2. Bulk SMS & Email Notifications
Critical communication channel for Nigerian schools
Medium Effort Admin · Finance
Infrastructure
1
Integrate SMS provider Integrate Africa's Talking or Termii API. Store API key in school settings. Track SMS units consumed per school.
2
Integrate Email provider Use Resend or SendGrid. Each school gets a sending identity (e.g. noreply@schoolname.caspaa.ng).
3
Add SMSLog & EmailLog tables Fields: id, schoolId, sentBy, recipients (count), message, channel, status, sentAt. Track delivery status.
UI & Views
4
Admin: SMS Compose view New view view_adm_sms — choose audience (All Parents / All Teachers / Specific Class), compose message, see character count & unit cost, send & confirm.
5
SMS Log history Table of past sends: audience, message preview, units used, delivery rate, timestamp.
6
Auto-triggers Trigger SMS on: invoice generated, payment received, new announcement, exam results published, event reminder.
Technical Notes
  • Numbers on DND (Do Not Disturb) consume more SMS units — warn admin in UI (already noted in EDVES pricing as a caveat).
  • Store remaining SMS balance in school settings; deduct on send; alert when balance < 50 units.
  • For demo mode: simulate API call with a 1.5s delay and mock success response.
Roles: Admin (Send) Finance (Fee alerts)

5. Maths & Science Simulations (PhET)
Embed free PhET interactive simulations — a key EDVES selling point
Low Effort Student · Teacher
Data & Setup
1
Create SimulationCatalog Static JS array of 30–50 curated PhET simulations: { id, name, subject, topic, gradeLevel, embedUrl, thumbnailUrl, description }. PhET is free, open source, no API key needed.
2
Cover Maths & Sciences Include: Build an Atom, Wave on a String, Projectile Motion, Ohm's Law, Fraction Matcher, Area Builder, Balancing Chemical Equations, etc.
UI & Views
3
Student: Simulations library New tab "Simulations" in stu_learning. Filter by subject (Maths / Physics / Chemistry / Biology). Card grid: thumbnail, name, topic, "Launch" button.
4
Simulation player Full-screen modal with PhET simulation in an iframe (PhET provides embed-ready URLs). No API key required.
5
Teacher: Assign simulations Teacher can "assign" a simulation to a class for a lesson — appears in student's dashboard as "Simulation this week".
Technical Notes
  • PhET simulations at phet.colorado.edu are free, open source, and embeddable without authentication.
  • Use the direct simulation HTML embed URLs — no dependency on external API.
  • HTML5 sims work on tablets and mobile; older Java sims require desktop — only catalogue HTML5 ones.
Roles: Student (Launch) Teacher (Assign)

6. Online Payment Gateway
Connect fee payments to Paystack or Flutterwave
High Effort Parent · Finance
Integration Steps
1
Add payment provider config to School Settings Admin enters Paystack/Flutterwave public key and secret key. Stored in school settings. Test mode toggle for sandbox.
2
Implement "Pay Now" flow (Parent) Parent clicks "Pay Now" on invoice → Paystack popup/redirect opens with invoice amount pre-filled → on success, callback fires.
3
Payment verification backend On callback, verify transaction reference with Paystack API. Only mark payment as successful after server-side verification.
Post-Payment Flow
4
Auto-create Transaction record On verified success: create Transaction with method=Card, amount, invoiceId, reference, status=Completed. Update invoice balance.
5
Send receipt SMS & email Auto-trigger SMS + email to parent with payment confirmation and receipt number. CC finance officer.
6
Finance dashboard update Online payments appear in fin_payments with a "Card" badge. Reconciliation queue auto-marks these as verified (no manual step needed).
Technical Notes
  • Use Paystack's inline JS for popup mode — no redirect, better UX.
  • Paystack charges 1.5% per transaction (capped at ₦2,000) — make this visible to parents before payment, as noted in EDVES pricing.
  • Store transaction reference in Transactions table for reconciliation and dispute resolution.
Roles: Parent (Pay) Finance (Receive) Admin (Configure)

8. Teacher Payslip (Self-View)
Teachers access their own monthly payslip — data already exists in payroll
Low Effort — Quick Win Teacher
Implementation Steps
1
Add "Payslip" to teacher menu New view view_tch_payslip. Pull current teacher's payroll records from existing Payroll/Salary data in DB.
2
Payslip card layout Term/month selector at top. Show: Gross Salary, Deductions breakdown (tax, pension, etc.), Net Pay, Bank Account, Payment Date, Payment Status. Print-ready format.
3
Salary advance status If teacher has a pending salary advance, show it on the payslip with status (Pending/Approved/Deducted).
4
PDF download Print/PDF button using window.print() with a payslip-specific print stylesheet. No external PDF library needed.
Access Control
5
Privacy: own data only Teacher can only see their own payslip. Query must filter by session.userId to prevent accidental data leaks.
6
Finance: Payslip history Finance officer can view/download payslips for any staff from fin_payroll. Existing payroll view — just add "View Payslip" action per row.
Roles: Teacher (Own only) Finance (All staff)

Phase 3 — Weeks 11–16+
Strategic & AI Differentiation

Phase 3 modules require deeper engineering investment or third-party integrations. They are the long-term differentiation layer — plan now, build after Phase 1 & 2 are stable.

Phase 3

6 Modules · Weeks 11–16+

Focus: AI integration, live learning infrastructure, multi-curriculum support, and offline capability.

Module What It Involves Why It Matters Estimated Effort
Virtual Classroom Embed Jitsi Meet or Zoom SDK for live classes. Schedule sessions linked to timetable. Teacher starts, students join from portal. EDVES has this. Needed for hybrid/remote school models which are growing post-COVID. 4–6 weeks
AI Grading & Question Generation Integrate Claude API. Teacher selects lesson note → AI suggests 10 CBT questions. AI also marks short-answer questions with justification. Reduces teacher workload by 40%. Clear differentiator vs. EDVES's current AI features. 6–8 weeks
Student Performance Prediction ML model (or rule-based heuristic) flagging students at risk based on: declining attendance, falling grades, missed assignments. Alert shown to teacher and admin. Early intervention tool. Schools pay premium for this insight. EDVES highlights it prominently. 6–8 weeks
Hostel Management Boarding schools only. Rooms, bedspace assignment, check-in/out records, meals schedule, lights-out tracking, parent visit authorization. Unlocks boarding school market. Currently zero boarding school support in CASPAA. 4–5 weeks
Multi-Curriculum Support Tag lessons, notes, and assessments with curriculum standard (NERDC / Cambridge / IGCSE / IB). Allow school to set default curriculum. Filter analytics by curriculum compliance. Required for international schools and premium market segment. EDVES's Cambridge/IGCSE support is a key differentiator in Lagos Island schools. 3–4 weeks
Offline CBT Service Worker + IndexedDB to cache exam questions. Students take exam offline; answers sync when connection restored. Tamper-proof with exam session token. Critical for schools in areas with unreliable internet. EDVES supports this; it blocks adoption in rural and peri-urban schools. 6–8 weeks
Appendix — Dependency Map
Build Order Dependencies

Some modules depend on others being built first. Follow this order to avoid rework.

1
Bulk SMS & Email must come first Communication Diary (Module 11), Health/Sickbay (13), Transport (9), and Payment Gateway (6) all depend on SMS/Email to send alerts. Build this before those modules.
2
Class Notes before Video Lessons Both live in stu_learning. Build the Notes tab structure first, then Video Lessons tab slots in alongside it. Shared learning hub UX is established once.
3
Formative Assessment before Multi-Curriculum (P3) Formative Assessment data model (week-based scoring) becomes the foundation for curriculum-tagged assessment in Phase 3.
4
House Point System can be built independently No dependencies on other new modules. Safe to start any time in Phase 2 in parallel with other work.
5
AI features (P3) depend on Class Notes and Results data AI question generation reads from existing ClassNotes content. Performance prediction reads from Results + Attendance — both of which must be populated with real data first.
